# AI 创意工作室架构优化 - 产品需求文档

## Overview
- **Summary**: 对 AI 创意工作室的生成功能架构进行优化，实现统一的生成服务接口、模型抽象、任务处理，以及前端状态管理优化。
- **Purpose**: 解决当前代码重复、架构不统一、扩展困难的问题，为后续添加新模型和功能提供清晰的架构基础。
- **Target Users**: 开发团队和最终用户。

## Goals
- 实现统一的生成服务接口和任务处理架构
- 建立模型抽象层，支持灵活切换和扩展模型
- 优化前端状态管理，提供统一的生成过程状态提示
- 确保所有生成功能页面都有图片质量、比例和模型切换选项
- 代码结构清晰，便于后续维护和扩展

## Non-Goals (Out of Scope)
- 不修改现有的数据库结构
- 不改变现有的积分系统逻辑
- 不实现新的生成功能，只优化现有功能的架构
- 不修改后端 API 路由的基础结构

## Background & Context
- 当前代码存在重复逻辑，如积分处理、文件保存等
- 不同生成功能的实现方式不一致，有的在服务层，有的在路由中
- 缺乏统一的模型管理机制，添加新模型需要修改多处代码
- 前端状态管理分散，用户体验不一致

## Functional Requirements
- **FR-1**: 创建统一的生成服务接口和任务处理架构
- **FR-2**: 实现模型抽象层，支持 flash、pro、image2 模型，并预留扩展接口
- **FR-3**: 优化前端状态管理，提供统一的生成过程状态提示
- **FR-4**: 确保所有生成功能页面都有图片质量、比例和模型切换选项
- **FR-5**: 实现生成过程中的按钮状态管理，确保生成中按钮不可点击

## Non-Functional Requirements
- **NFR-1**: 代码结构清晰，符合模块化设计原则
- **NFR-2**: 性能要求，生成过程的状态更新响应及时
- **NFR-3**: 可扩展性，便于后续添加新模型和生成功能
- **NFR-4**: 可维护性，代码文档完善，逻辑清晰

## Constraints
- **Technical**: 基于现有的 Next.js 16、TypeScript、Prisma 技术栈
- **Dependencies**: 依赖现有的 AI API（Google Gemini、OpenRouter）

## Assumptions
- 现有的数据库结构和积分系统保持不变
- 现有的 API 路由结构基本保持不变
- 前端使用 Zustand 进行状态管理

## Acceptance Criteria

### AC-1: 统一的生成服务架构
- **Given**: 开发环境已搭建
- **When**: 实现统一的任务处理架构
- **Then**: 所有生成功能（文生图、局部重绘、进阶设计、Agent 图片）使用统一的服务接口
- **Verification**: `human-judgment`

### AC-2: 模型抽象层
- **Given**: 模型抽象架构已实现
- **When**: 添加新模型时
- **Then**: 只需实现模型接口并注册，无需修改现有代码
- **Verification**: `programmatic`

### AC-3: 前端状态管理优化
- **Given**: 前端状态管理已优化
- **When**: 用户触发生成任务
- **Then**: 所有页面显示统一的生成状态提示，按钮显示为"生成中"且不可点击
- **Verification**: `human-judgment`

### AC-4: 统一的参数选项
- **Given**: 所有生成功能页面
- **When**: 用户访问生成页面
- **Then**: 页面显示图片质量、比例和模型切换选项
- **Verification**: `human-judgment`

### AC-5: 代码可维护性
- **Given**: 架构优化完成
- **When**: 开发人员查看代码
- **Then**: 代码结构清晰，模块化程度高，便于理解和维护
- **Verification**: `human-judgment`
